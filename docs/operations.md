# Диагностика и эксплуатация

## Обновление базы

Исходники миграций находятся в backend/migrations. Применение локально без сброса данных:

```bash
node backend/scripts/cli.mjs migration up --local
npm run db:types
npm run db:test
npm run test:api:local
npm run test:postgres:local
npm run test:ui:local
```

Миграции 003–004 сохраняют существующие записи. Создание поддерживает необязательный p_request_id;
вызовы старого контракта без ключа продолжают работать. Клиент нужно публиковать после миграций.
Для облака используется авторизованный CLI через тот же wrapper и db push.

## Ошибки приложения

Неожиданные ошибки React, запросов, команд и глобальных обработчиков регистрируются через
report_client_error. Ожидаемые доменные отказы и отменённые запросы не считаются сбоями.
Событие содержит UUID, текущего пользователя, категорию, безопасный код, шаблон маршрута,
версию приложения и время БД. Тексты ошибок, стек, URL с параметрами, содержимое CRM,
пароли и токены не отправляются. При недоступной базе остаётся безопасная запись в консоли браузера.
До авторизации доступна только локальная консоль; серверный приём требует authenticated.

Прочитать диагностику может администратор БД, например через SQL Editor:

```sql
select id, source, code, route, release, created_at
from private.client_errors
where created_at >= now() - interval '1 day'
order by created_at desc
limit 100;
```

Рекомендуемое обслуживание администратором: сохранять диагностику 30 дней, бюджеты — сутки.
Эти команды не удаляют задачи, аудит или ключи создания:

```sql
delete from private.client_errors where created_at < now() - interval '30 days';
delete from private.client_error_budgets where minute < now() - interval '1 day';
```

Задание очистки и внешние алерты в облачной инфраструктуре ещё не настроены.
Приватный журнал creation_requests нужен для безопасного повтора создания и содержит входные
данные команды; доступ ограничен доверенным backend и администраторами БД. Не удаляйте ключи
произвольно: после их удаления прежний запрос снова сможет создать запись.

## Производительность

```bash
npm run db:profile
```

Команда разрешена только для локального PostgreSQL. В одной транзакции добавляет 100 объектов
и 10000 задач, выполняет EXPLAIN ANALYZE под authenticated с ролями постановщика/исполнителя,
затем откатывает все тестовые данные. Статистика таблиц обновляется после отката.
Полные планы — .local/query-profile.json, в консоли — только имена запросов и длительности.

На локальном PostgreSQL 17 после изменения RLS подсчёт 10000 задач занял 2,2–2,4 мс
вместо 68 мс, список объектов исполнителя — 0,55 мс вместо 68 мс.
Это отдельные локальные замеры, без сетевой задержки и конкурентной нагрузки; они не являются SLA.

Для промышленной эксплуатации отдельно нужны нагрузочный профиль компании, проверка восстановления
резервных копий, алерты и проверка облачной конфигурации. Эти действия требуют инфраструктуры
развёртывания и не заменяются успешной локальной сборкой.
